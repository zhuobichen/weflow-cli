# WeFlow CLI 整体改进与扩展计划书

> 版本：草案 v1.0  
> 适用范围：`weflow-cli` 主仓库、CLI、MCP、本地阅读器，以及基于公开数据契约的合作集成。  
> 本文描述方向、分期、验收标准与维护机制；当前已实现能力以 [PROJECT_STATE.md](PROJECT_STATE.md) 为准。

## 一、定位与目标

WeFlow CLI 的长期定位是**用户授权的本地数据底座**：在用户设备上，将本地聊天、公众号阅读、收藏与知识资料整理为可查询、可导出、可被 AI 或合作应用在明确边界内使用的数据能力。

项目不以替代官方客户端或进行账号自动化为目标。核心价值是让用户能够在本地完成资料整理、阅读、检索、导出、复盘与受控分析，并为上层产品提供稳定、可审查的接口。

未来 12 至 18 个月的目标：

1. **稳定可用**：初始化、数据库访问、导出与日报在支持的平台上有清晰诊断、可重试路径和回归验证。
2. **数据可信**：消息、媒体、来源、时间范围和导出覆盖状态可被追溯；宁可标记缺失，也不误配内容。
3. **AI 可控**：本地流程默认可不用 AI；需要云端 AI 时，让用户看得见输入范围、成本与执行结果。
4. **面向合作扩展**：以版本化 JSON 数据契约和只读 MCP 为边界，让 `she-love-me` 等合作项目可以接入，而不触及数据库、密钥或本地目录。
5. **长期可维护**：让后续维护者和 Agent 能从项目状态、决策记录、测试与问题模板快速理解现状并连续推进。

## 二、发展原则

| 原则 | 具体要求 |
| --- | --- |
| 本地优先 | 原始聊天数据、数据库访问凭据、导出文件默认保留在用户设备；不把真实数据写入仓库、测试或公开报告。 |
| 用户授权 | 仅处理用户本人拥有或明确获授权的数据；涉及写入、发布、云端处理与长期服务时采用预览和确认。 |
| 准确优先 | 媒体、联系人与会话匹配必须依赖可靠身份；无法可靠对应时显示占位与原因，不以猜测填充。 |
| 兼容演进 | CLI 人类可用输出保持稳定；面向工具的 JSON/MCP 接口采用版本化、可扩展、保留未知字段的方式演进。 |
| 默认最小权限 | MCP 默认只读；助手默认拒绝陌生来源；本地阅读器仅监听回环地址。 |
| 可验证交付 | 每项功能都要有明确入口、成功条件、失败诊断和与风险相称的自动化或本机验证。 |

## 三、现状与主要缺口

| 能力线 | 已有基础 | 主要缺口 |
| --- | --- | --- |
| 本地聊天数据 | 会话、联系人、消息、收藏、朋友圈缓存与多格式导出；支持部分 NT 媒体和 HTML 阅读 | 微信版本与媒体格式变化快；资源库映射、图片/表情/视频覆盖率仍需提升；导出覆盖情况需要更清晰地呈现。 |
| 初始化与诊断 | 复用已验证配置、按需刷新、路径发现、缺失密钥测试 | 支持场景需要形成更标准的诊断包与兼容性矩阵，减少 Issue 中的反复沟通。 |
| 公众号日报 | 来源筛选、分类、补昨日报、无 AI 运行、HTML 阅读器、收藏同步 | 需要提升抓取韧性、增量更新、阅读质量与定时任务可观测性。 |
| 知识与 AI | Vault、检索、RAG、阅读笔记、报告和隐私模式 | 需要统一数据选择、成本提示、结果引用、可复现评估与本地模型体验。 |
| Agent/MCP | 只读 MCP、能力发现、版本化消息数据契约 | 工具覆盖仍不完整；需要稳定分页/增量同步、模拟数据集与合作接入指南。 |
| 工程治理 | 项目状态、技术决策、安全说明、测试与 CI | 需要路线图、发布节奏、依赖治理、性能基线与更结构化的 Issue/PR 流程。 |

## 四、分期路线

### P0：可靠性与导出修复

**目标：** 让用户最常使用的初始化、查询和 HTML 导出流程稳定、可解释。

| 工作项 | 交付物 | 验收标准 |
| --- | --- | --- |
| 初始化兼容性 | 支持版本/平台矩阵、脱敏诊断命令、常见失败决策树 | 在支持版本上可完成配置验证；失败结果能区分路径、运行环境、数据库访问与客户端状态问题。 |
| 媒体导出可靠性 | 会话级缓存索引、图片/表情/转发卡片渲染、媒体覆盖统计 | HTML 能展示可可靠关联的本地媒体；无法匹配的记录不出现错图；导出完成后报告图片、表情、链接与占位数量。 |
| 导出性能 | 本地媒体优先、远程资源预算、可选的离线模式 | 大会话导出不会因外部封面请求无限等待；离线模式可在无网络时完成本地内容导出。 |
| 回归样本 | 完全合成的数据库/缓存夹具与真实机脱敏验证清单 | 每种媒体分支至少有合成回归；发布前按清单完成一次本机真实验证。 |

**优先顺序：** 先修复数据错配和导出失败，再增加新媒体格式；所有“显示更多内容”的改动都必须先证明不会把无关媒体关联到消息。

### P1：数据底座与稳定接口

**目标：** 将当前 CLI 能力整理为可供其他本地应用和 Agent 安全调用的数据层。

| 工作项 | 交付物 | 验收标准 |
| --- | --- | --- |
| 数据契约完善 | `weflow-message/v1` 补充媒体状态、来源字段、覆盖信息和兼容策略 | 下游应用无需读取数据库即可消费消息；未知类型、缺失媒体和分页边界均有明确语义。 |
| 增量同步 | 基于时间窗的重叠读取、去重建议、稳定的同步状态文件 | 重新运行不会遗漏边界消息；下游能判断结果是否可能不完整。 |
| MCP 扩展 | 与 CLI 共享的只读工具：会话发现、分页读取、导出任务状态、日报读取 | 工具输入有上限和校验；响应不包含密钥、路径、未授权会话或完整无界数据。 |
| 数据质量报告 | `check` 或独立只读命令输出结构化健康摘要 | 用户可看到数据库可读性、媒体覆盖、日报完整性与配置状态，而不暴露敏感内容。 |
| 合作接入包 | 合作方 README、模拟数据、兼容性测试和最小示例 | 合作项目可在没有真实微信数据的环境中完成开发与集成测试。 |

### P2：日报与个人知识工作流

**目标：** 把公众号阅读、收藏、笔记和知识检索变成连续且可控的个人工作流。

| 工作项 | 交付物 | 验收标准 |
| --- | --- | --- |
| 日报韧性 | 来源健康状态、失败重试、去重、补报记录、生成摘要 | 当天或昨日报缺失时能说明原因并可重跑；不会重复写入同一篇文章。 |
| 阅读器体验 | 来源/类别筛选、搜索、阅读进度、收藏与本地笔记关联 | 所有状态保存在本地；刷新后阅读和收藏状态可恢复。 |
| 来源配置 | 来源类别、白名单/停用状态、来源发现与导入导出 | 已分类来源不重复调用主题分类；用户可迁移自己的来源配置。 |
| 知识沉淀 | 将日报、收藏和用户笔记转成可追溯的 Vault 条目 | 每条知识条目保留来源、日期和原始链接；生成内容与原始材料可区分。 |
| 定时运行 | 可查看、可暂停、可重跑的本地任务状态 | 定时任务失败会留下脱敏状态与下一步建议；不会静默重复启动阅读器。 |

### P3：受控 AI 与个人助手

**目标：** 让 AI 成为用户的本地数据助手，而不是不透明的数据出口。

| 工作项 | 交付物 | 验收标准 |
| --- | --- | --- |
| 统一 AI 执行层 | 模型、端点、隐私模式、输入上限、成本预估与执行审计的统一配置 | 每次云端调用可说明发送范围和模型；关闭 AI 后所有非 AI 流程仍完整可用。 |
| 检索与问答质量 | 引用原始片段、时间/来源筛选、回答置信提示与反馈入口 | 回答能指出使用了哪些本地材料；不把检索结果当作未经核实的事实。 |
| 法律线索辅助 | 面向用户选择的材料进行事件线索、时间线和证据清单整理 | 输出明确标记为线索整理，不替代法律意见；原始材料、导出副本和分析结果可独立保存。 |
| 助手权限模型 | 会话/群组级白名单、只读工具选择、人工确认的写操作 | 默认拒绝；任何外发、写入或发布均经过预览与明确确认。 |
| 本地模型支持 | 本地模型发现、能力检测、降级策略和性能说明 | 未配置云端密钥时，支持的本地模型可完成基础检索与摘要。 |

### P4：生态合作与可持续维护

**目标：** 让项目可被可靠复用、协作开发和长期维护。

| 工作项 | 交付物 | 验收标准 |
| --- | --- | --- |
| 合作模式 | 数据契约版本策略、兼容性承诺、模拟集与集成 CI | 下游项目升级时可自动发现不兼容变更；合作方不能越过本地权限边界。 |
| 插件/适配器机制 | 受限的本地适配器接口与能力声明 | 第三方扩展无法直接读取配置、数据库或任意文件；扩展能被单独禁用。 |
| 发布治理 | 版本号、变更日志、GitHub Release、npm 发布核对表 | GitHub 源码、编译包和 npm 版本的差异对用户可见；发布前完成构建、测试和敏感信息检查。 |
| 社区协作 | Issue 模板、兼容性反馈模板、PR 检查清单、贡献者指南 | 问题报告可复现且脱敏；外部贡献可通过自动检查与人工审阅。 |
| 可观测性 | 本地匿名/脱敏运行摘要与性能基线 | 不采集真实聊天内容；维护者可定位慢导出、抓取失败和兼容性回归。 |

## 五、横向工程专项

### 1. 测试策略

- **单元测试：** 路径解析、输入验证、数据契约、隐私过滤、媒体匹配和 AI 路由。
- **合成集成测试：** 通过不含真实聊天内容的模拟数据库、缓存文件和 HTTP 夹具验证初始化、导出、日报与 MCP。
- **本机验收清单：** 在用户授权的本地环境中验证会话读取、日期导出、图片/表情/链接、日报生成与阅读器启动；结果只记录计数和状态。
- **兼容性回归：** 对每个支持的微信版本、操作系统和安装位置记录验证日期、通过项和已知限制。

### 2. 性能与资源预算

- 为导出、媒体扫描、日报抓取、索引和 AI 请求设定时间、文件大小、数量和内存上限。
- 大任务提供进度、可取消能力和明确的部分完成状态。
- 优先会话范围、日期范围和增量处理，避免无边界扫描全部数据。
- 对远程封面、网页抓取和云端 AI 建立独立预算，使它们不阻塞本地核心流程。

### 3. 安全与隐私治理

- 新增外部网络访问、MCP 工具、写操作或数据导出格式时，先检查 `SECURITY.md` 与 `DECISIONS.md`。
- 所有日志、测试夹具、Issue 示例和 CI 产物使用合成或脱敏数据。
- 密钥仅从加密配置或环境变量进入子进程，绝不写入命令行、HTML、报告或版本库。
- 定期审查依赖漏洞；升级先在独立改动中验证，不使用未经验证的破坏性自动修复。

## 六、里程碑与验收节奏

| 里程碑 | 建议周期 | 通过条件 |
| --- | --- | --- |
| M1：稳定导出 | P0 完成时 | 初始化、会话读取和 HTML 导出在支持环境可复现；媒体不发生已知错配；导出不会被外部网络长期阻塞。 |
| M2：数据底座 v1 | P1 完成时 | CLI JSON 与 MCP 使用同一版本化契约；模拟集和合作接入示例可独立运行。 |
| M3：阅读与知识闭环 | P2 完成时 | 公众号来源配置、日报、收藏和 Vault 之间可本地追溯，补报与失败恢复可验证。 |
| M4：受控 AI 助手 | P3 完成时 | AI 调用范围、隐私模式、成本与引用可见；默认权限和确认机制通过回归。 |
| M5：生态发布 | P4 完成时 | 发布流程、兼容性检查、合作接入和社区反馈机制形成稳定闭环。 |

每个里程碑使用以下最小交付清单：功能说明、数据/权限边界、测试证据、已知限制、文档更新、可回滚方案。未满足这些条件的实验能力不进入默认工作流。

## 七、优先级与资源建议

### 必须优先投入

1. 初始化和数据库兼容性。
2. 导出准确性、媒体覆盖和性能。
3. 数据契约与 MCP 的稳定性。
4. 日报的可靠生成与本地阅读体验。
5. 安全边界、文档和回归测试。

### 条件成熟后推进

1. 多模型和更复杂的 AI 分析。
2. 法律线索整理与结构化证据包。
3. 插件生态和更多外部合作。
4. 更多平台与客户端版本的兼容适配。

### 暂不纳入默认能力

- 个人微信账号自动发消息、拉群、群管理或未验证的客户端自动化。
- 向第三方直接暴露数据库、密钥、完整本地目录或无范围限制的聊天内容。
- 无用户确认的云端分析、自动发布或跨设备同步。

## 八、维护机制

1. **每次改动先定位能力线：** 归入 P0–P4 或横向专项；没有对应目标的改动应说明必要性。
2. **每次功能变更同步文档：** 用户可见行为更新 README/CHANGELOG，现状更新 `PROJECT_STATE.md`，长期取舍更新 `DECISIONS.md`。
3. **每周维护检查：** 查看 Issue、PR、依赖告警、兼容反馈与定时任务状态；仅记录脱敏摘要。
4. **每个发布前复核：** 构建、回归测试、媒体专项测试、敏感信息扫描、源代码与编译产物路径验证。
5. **每季度复盘路线：** 根据真实 Issue、成功率、导出覆盖、日报完成率和合作集成反馈调整优先级，而不是仅按功能数量衡量进展。

## 十、成功标准

路线完成不是命令数量增加，而是达到以下状态：

- 用户可以在支持环境中用清晰步骤完成初始化、读取、导出与日报生成，并在失败时得到不泄露隐私的可操作提示。
- 导出的内容能够说明哪些媒体和链接被完整保留、哪些没有可靠来源，且不会误配他人或其他会话的媒体。
- AI、MCP 与合作项目只使用用户明确允许的、范围受限的数据接口。
- 项目维护者或新的 Agent 能仅依靠仓库文档、测试与模拟数据继续开发，而不依赖真实聊天记录或口头记忆。
