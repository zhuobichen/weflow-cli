# 方法 × 微信版本 对照表

> **为什么要这张表**：微信每次升级都可能让某个"取数据的方法"失效，而失效**不会报错**——
> 它只是开始返回空、返回假数据，或者报一句误导性的错误（实测：4.2 上 `pymem`
> 枚举不到 `Weixin.exe`，程序因此说"微信未运行"，而当时微信明明开着）。
>
> 所以每个方法都必须登记：**适用版本**、**失效原因**、**换成了什么**。
> 表格由 `test/version_methods_test.py` 校验：标为"失效"的行必须写清原因和替代，
> 且必须带证据日期。**新增方法不登记，测试会红。**

## 怎么加新行

1. 先写**观察**：哪个方法、在哪个版本、观察到什么（空结果？假错误？）。
2. 把**原因**写到能解释"为什么"的程度（是哪一层变了，不是"就是不work"）。
3. 写清**替代**；没有替代就写"无"，并说明为什么这条路本身不承载数据。
4. 带**日期**，必要时指向 `docs/DECISIONS.md` 的 D-编号。

> 反面教材（本仓库真实踩过）：把"我的枚举方法看不到进程"写成"微信没在运行"，
> 于是用户被引导去重装 Python——而依赖全是 ✓。**假错误比没结果更贵**：
> 它会让下一个人沿着错误的方向排查一整天。
